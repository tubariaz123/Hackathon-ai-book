# Data Model: URL Ingestion, Embeddings, and Vector Storage

## Document Chunk Entity

**Description**: Represents a segment of text extracted from a book page, including the original URL, content, and metadata.

**Fields**:
- `id` (string): Unique identifier for the chunk
- `url` (string): Source URL of the content
- `content` (string): Text content of the chunk
- `title` (string): Page title from the source
- `created_at` (datetime): Timestamp when chunk was created
- `chunk_index` (integer): Position of chunk within the original document

**Validation Rules**:
- `url` must be a valid URL format
- `content` must not be empty
- `content` length should be within Cohere token limits

## Embedding Vector Entity

**Description**: Numerical representation of text content generated by Cohere, stored in Qdrant with associated metadata.

**Fields**:
- `vector_id` (string): Unique identifier for the vector in Qdrant
- `embedding` (list[float]): Vector representation from Cohere
- `document_chunk_id` (string): Reference to the source document chunk
- `metadata` (dict): Additional metadata including source URL, title, etc.

**Validation Rules**:
- `embedding` must have the correct dimension (1024 for Cohere models)
- `document_chunk_id` must reference an existing document chunk
- `metadata` must include required fields (url, title)

## Crawled Page Entity

**Description**: Information about a page discovered during crawling, including URL, title, and extracted content.

**Fields**:
- `url` (string): The page URL
- `title` (string): Page title from HTML
- `content` (string): Extracted text content
- `crawled_at` (datetime): Timestamp when page was crawled
- `status` (string): Crawl status (success, error, etc.)

**Validation Rules**:
- `url` must be unique within the crawl session
- `url` must be from the same domain as the root URL
- `content` must not be empty for successful crawls
